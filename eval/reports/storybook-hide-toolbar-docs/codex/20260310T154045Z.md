## Final Summary

Implementation A appears closer architecturally by working within manager-api modules and staying manager-side, but its diff is dominated by tooling artifacts and truncated. Implementation B is cleaner and more complete but diverges significantly: it creates standalone utilities instead of extending layout.ts, adds CSF parameter support the PR doesn't have, modifies preview-api code, duplicates logic across components, and uses a fundamentally different callback signature. B is likely the better standalone implementation due to clarity and completeness, but A better matches the PR's architectural intent of extending existing manager infrastructure.
